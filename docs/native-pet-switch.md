# Codex 原生宠物切换问题

用户在 2026-10-23 报告：内置宠物间切换正常；从内置宠物切到妮可后宠物消失，但设置仍显示已开启。手动隐藏、再显示后妮可恢复。

后续补充：没有主动隐藏时也会消失；**角色与下方输入/任务控件一起消失，Option + Space 可以一起恢复**。这说明需要排查整个原生浮层的显示状态，不只是图片透明或某张动画帧为空。

本次检查客户端为 macOS Codex 26.1016.62342（21477）。本地 v2 图集的所有已用帧都有非透明像素，空余单元透明；文件尺寸、清单和校验值与发布资源一致。已保存的显示开关为开启。上述文件检查不能证明运行中的窗口可见。

只读检查客户端发现：自定义角色需要异步加载，在角色尚未解析时，浮层有返回空内容的路径。它是值得排查的切换差异，但没有复现证据能证明它导致持续消失。未修改客户端、账号配置或私有偏好。

已核实：

- 原包为有效的 1536×1872 RGBA WebP，9 行动画，首个 idle 单元非空；清单可被当前安装的 Codex 读取。旧版未声明 `spriteVersionNumber`，当前客户端默认值为 1，故缺少该字段本身不构成格式错误。
- 当前安装的客户端同时支持版本 1（9 行）与版本 2（11 行）；内置宠物为版本 2。新格式在最后两行放置 16 个视线方向。
- 本仓库准备了明确声明版本 2 的 1536×2288 包，保留原 9 行、追加由原眼睛像素加工的视线帧，并清理绿色抠图边缘。旧版仍可用 `--legacy` 安装。
- 目前没有日志证据能确定根因。升级用于消除格式差异和启用原生视线跟随，不能当作已证实的切换修复。

回归步骤：安装新包，完全退出并重开 Codex 以刷新自定义宠物缓存；保持宠物显示，按「内置 → 妮可 → 另一内置 → 妮可」切换，重复三轮，并移动鼠标检查视线。记录是否需要再次隐藏/显示。

若仍复现，临时使用隐藏/显示恢复，并记录客户端版本及复现步骤。原生包不能修补 Codex 客户端的窗口生命周期。不要修改已签名的 Codex 应用、私有账号状态或用户偏好来强行绕过问题。

v0.4.0 修正的范围：相同资源重复安装不再覆盖文件；更新先完成临时文件，再进行重命名；切换 v1/v2 时保留旧图集，最后切换清单。测试在每次重命名之前/之后检查清单仍能读到对应格式的图集。这消除了安装器造成部分写入的风险，**不是已经验证的 Codex 窗口消失修复**。

v0.5.0 新增独立 Nicole Pet App。它使用自己的透明窗口，因此不依赖 Codex 原生宠物浮层；如果用户只需要稳定的独立角色和互动，可以运行该 App，而不是切换 Codex 原生宠物。

只读诊断命令：`node skills/nicole-pet/scripts/doctor.cjs`。文件通过后优先按 [官方宠物说明](https://learn.chatgpt.com/docs/pets) 在设置中 Refresh，使用自己的「显示宠物」快捷键恢复，再做完整重启与切换回归；不要把重新生图或盲目降级作为修复。

本项目自动化工具无法操作 Codex 自身界面，因此切换回归需要用户实际确认；本机日志与客户端代码仅作只读诊断，未打包到公开仓库。
